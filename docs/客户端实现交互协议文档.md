# 小智服务器客户端实现交互协议文档

## 概述

本文档详细描述了如何实现与小智服务器进行交互的客户端。小智服务器是一个基于WebSocket的实时语音交互系统，支持语音识别(ASR)、语音合成(TTS)、大语言模型(LLM)对话、视觉识别、以及MCP(Model Control Protocol)工具调用。

## 1. 连接建立

### 1.1 WebSocket连接
- **连接地址**: `ws://服务器IP:8000/`
- **协议**: WebSocket协议
- **传输层**: TCP

### 1.2 必需的HTTP头部信息
客户端连接时必须在HTTP头部包含以下信息：

```http
Upgrade: websocket
Connection: upgrade
Sec-WebSocket-Key: [随机Base64密钥]
Sec-WebSocket-Version: 13
Device-Id: [设备唯一标识，格式如 94:a9:90:14:ca:34]
Client-Id: [客户端唯一标识，UUID格式]
Protocol-Version: 1
```

可选头部：
```http
Session-Id: [会话ID，如果不提供会自动生成]
X-Real-Ip: [真实IP地址]
X-Forwarded-For: [转发IP地址]
X-Forwarded-Proto: [协议类型，http/https]
```

### 1.3 连接建立流程
1. 客户端发起WebSocket握手请求
2. 服务器验证头部信息并升级连接
3. 服务器分配资源池（ASR、LLM、TTS、VLLLM、MCP资源）
4. 服务器启动多个消息处理协程
5. 连接建立成功

## 2. 消息格式规范

### 2.1 消息类型
WebSocket支持两种消息类型：
- **类型1 (文本消息)**: JSON格式的控制消息
- **类型2 (二进制消息)**: 音频数据（Opus或PCM格式）

### 2.2 基础消息结构
所有文本消息都遵循以下JSON结构：
```json
{
    "type": "消息类型",
    "session_id": "会话ID",
    // 其他字段根据消息类型变化
}
```

## 3. 连接初始化协议

### 3.1 客户端Hello消息
连接建立后，客户端必须首先发送hello消息：

```json
{
    "type": "hello",
    "version": 1,
    "transport": "websocket",
    "audio_params": {
        "format": "opus",           // 音频格式：opus 或 pcm
        "sample_rate": 16000,       // 采样率：8000/12000/16000/24000/48000
        "channels": 1,              // 声道数：1(单声道) 或 2(立体声)
        "frame_duration": 60        // 帧长度：60ms
    },
    "features": {
        "mcp": true                 // 是否支持MCP协议
    }
}
```

### 3.2 服务器Hello响应
服务器会响应hello消息，告知服务器音频参数：

```json
{
    "type": "hello",
    "version": 1,
    "transport": "websocket",
    "session_id": "device-94_a9_90_14_ca_34",
    "audio_params": {
        "format": "opus",           // 服务器音频格式
        "sample_rate": 24000,       // 服务器采样率
        "channels": 1,              // 服务器声道数
        "frame_duration": 60        // 服务器帧长度
    }
}
```

## 5. 语音交互协议

### 5.1 启动语音识别
客户端发送listen消息开始语音识别：

```json
{
    "type": "listen",
    "mode": "auto",        // 拾音模式：auto/manual/realtime
    "state": "start"       // 状态：start/stop/detect
}
```

拾音模式说明：
- **auto**: 自动模式，检测到语音后自动识别并处理
- **manual**: 手动模式，需要手动停止才会处理识别结果
- **realtime**: 实时模式，实时识别并打断当前TTS播放

### 5.2 停止语音识别
```json
{
    "type": "listen",
    "state": "stop"
}
```

### 5.3 文本检测消息
```json
{
    "type": "listen",
    "state": "detect",
    "text": "检测到的文本内容"
}
```

### 5.4 音频数据发送
- **消息类型**: 2 (二进制消息)
- **音频格式**: Opus编码，60ms帧长
- **采样率**: 16000Hz (客户端) / 24000Hz (服务器)
- **声道**: 单声道
- **编码参数**: 
  - Application: VoIP
  - Frame Duration: 60ms
  - 比特率: 自动

音频数据发送流程：
1. 客户端录音获取PCM数据
2. 使用Opus编码器编码为60ms帧
3. 通过WebSocket发送二进制消息（类型2）
4. 服务器接收后解码为PCM送ASR识别

## 6. 服务器消息类型详解

### 6.1 STT消息（语音识别结果）
```json
{
    "type": "stt",
    "text": "识别到的文本内容",
    "session_id": "device-94_a9_90_14_ca_34"
}
```

### 6.2 TTS状态消息
```json
{
    "type": "tts",
    "state": "start",              // start/sentence_start/sentence_end/stop
    "session_id": "device-94_a9_90_14_ca_34",
    "text": "要合成的文本",
    "index": 1,                    // 文本片段索引
    "audio_codec": "opus"          // 音频编码格式
}
```

TTS状态说明：
- **start**: 开始TTS处理
- **sentence_start**: 开始发送某句话的音频
- **sentence_end**: 某句话的音频发送完成
- **stop**: 所有TTS处理完成

### 6.3 LLM情绪消息
```json
{
    "type": "llm",
    "text": "🤔",                     // 情绪表情符号
    "emotion": "thinking",         // 情绪状态
    "session_id": "device-94_a9_90_14_ca_34"
}
```

支持的情绪状态：
- neutral(😐), happy(😊), laughing(😂), funny(🤡), sad(😢), angry(😠)
- crying(😭), loving(🥰), embarrassed(😳), surprised(😮), shocked(😱)
- thinking(🤔), winking(😉), cool(😎), relaxed(😌), delicious(😋)
- kissy(😘), confident(😏), sleepy(😴), silly(🤪), confused(😕)

### 6.4 音频数据接收
- **消息类型**: 2 (二进制消息)
- **格式**: Opus编码的音频帧
- **帧长**: 60ms
- **采样率**: 24000Hz
- **处理**: 客户端接收后解码播放

## 8. 音频处理技术细节

### 8.1 Opus编码配置
```go
OpusEncoderConfig{
    SampleRate:    16000,          // 客户端采样率
    MaxChannels:   1,              // 单声道
    Application:   opus.AppVoIP,   // VoIP应用优化
    FrameDuration: opus.Framesize60Ms // 60ms帧长
}
```

### 8.2 音频帧发送时序
服务器发送音频时采用时间同步机制：
1. 预缓冲3帧提升播放流畅度
2. 按60ms间隔发送后续帧
3. 支持中断和轮次检查
4. 自动清理过期音频

### 8.3 PCM音频格式
- **采样率**: 16000Hz (客户端录音) / 24000Hz (服务器TTS)
- **位深**: 16位
- **声道**: 单声道
- **字节序**: 小端序
- **格式**: 有符号整数

## 9. 错误处理

### 9.1 连接异常
- WebSocket连接异常时自动清理资源
- 资源池自动回收ASR、LLM、TTS、VLLLM、MCP资源
- 日志记录详细错误信息

### 9.2 音频解码错误
- Opus解码失败时fallback到原始数据
- 记录详细解码错误日志
- 继续处理后续音频帧

## 10. 客户端实现指南

### 10.1 必需组件
1. **WebSocket客户端**: 支持二进制和文本消息
2. **Opus编解码器**: 处理音频数据
3. **JSON解析器**: 处理控制消息
4. **音频录放模块**: 录音和播放功能
5. **MCP协议处理**: 工具注册和调用机制

#### 步骤4：音频处理
```javascript
// 录音并发送音频数据
async function startRecording() {
    const stream = await navigator.mediaDevices.getUserMedia({
        audio: {
            sampleRate: 16000,
            channelCount: 1,
            echoCancellation: true,
            noiseSuppression: true
        }
    });
    
    // 使用AudioWorklet处理音频
    const audioContext = new AudioContext({ sampleRate: 16000 });
    const processor = new AudioWorkletProcessor();
    
    processor.port.onmessage = (event) => {
        const pcmData = event.data;
        // 编码为Opus并发送
        const opusData = encodeToOpus(pcmData);
        ws.send(opusData); // 发送二进制消息（类型2）
    };
}

// 接收并播放音频
ws.onmessage = (event) => {
    if (event.data instanceof ArrayBuffer) {
        // 二进制音频数据
        const opusData = new Uint8Array(event.data);
        const pcmData = decodeOpus(opusData);
        playAudio(pcmData);
    } else {
        // 文本消息
        const message = JSON.parse(event.data);
        handleTextMessage(message);
    }
};
```

```javascript
}
```

### 10.3 状态管理
客户端需要维护以下状态：
- **连接状态**: 已连接/断开/重连中
- **MCP状态**: 未初始化/已初始化/工具已注册
- **音频状态**: 录音中/播放中/空闲
- **对话状态**: 对话轮次、当前处理状态

### 10.4 资源管理
- **音频资源**: 及时释放录音/播放资源
- **编解码器**: 重用Opus编解码器实例
- **缓冲区**: 合理设置音频缓冲区大小
- **连接资源**: 异常时自动清理WebSocket连接

## 11. 完整交互流程示例

### 11.1 典型语音对话流程
```
1. [客户端] 建立WebSocket连接 (带设备ID等头部)
2. [服务器] 连接成功，分配资源
3. [客户端] 发送hello消息 (音频参数)
4. [服务器] 响应hello消息 (服务器音频参数)
5. [服务器] 发送MCP初始化消息
6. [客户端] 响应MCP初始化
7. [服务器] 请求工具列表
8. [客户端] 返回支持的工具列表
9. [客户端] 发送listen start消息开始录音
10. [客户端] 持续发送Opus音频数据
11. [服务器] 发送STT消息 (识别结果)
12. [服务器] 发送情绪消息 (thinking 🤔)
13. [服务器] 发送TTS start消息
14. [服务器] 发送TTS sentence_start消息
15. [服务器] 持续发送音频帧数据
16. [客户端] 播放接收到的音频
17. [服务器] 发送TTS sentence_end消息
18. [服务器] 发送TTS stop消息
19. [循环] 重复步骤9-18进行多轮对话
```

### 11.2 MCP工具调用流程
```
1. [服务器] LLM决定需要调用客户端工具
2. [服务器] 发送MCP工具调用请求
3. [客户端] 执行本地工具功能
4. [客户端] 返回工具执行结果
5. [服务器] 基于工具结果继续LLM处理
6. [服务器] 发送最终回复的TTS音频
```

## 12. 错误处理和重连机制

### 12.1 连接异常处理
- 网络断开时客户端应实现自动重连
- 重连时重新发送hello和MCP初始化消息
- 维护断线前的对话上下文

### 12.2 音频异常处理
- Opus编解码失败时记录错误并跳过该帧
- 缓冲区溢出时清空缓冲区重新开始
- 采样率不匹配时进行重采样处理

### 12.3 MCP协议异常
- 工具调用超时(30秒)后返回错误
- 不支持的工具调用返回相应错误码
- JSON格式错误时忽略该消息

## 13. 性能优化建议

### 13.1 音频优化
- 使用音频缓冲队列平滑播放
- 合理设置预缓冲帧数（建议3帧）
- 及时清理已播放的音频数据

### 13.2 网络优化
- 实现消息队列避免WebSocket阻塞
- 使用二进制格式发送音频数据
- 合理设置WebSocket缓冲区大小

### 13.3 资源优化
- 重用Opus编解码器实例
- 及时释放音频文件句柄
- 实现对象池管理音频缓冲区

## 14. 安全考虑

### 14.1 身份验证
- Device-Id必须是设备的唯一标识
- 服务器可能要求设备认证才能使用完整功能
- Token机制用于访问视觉服务等高级功能

### 14.2 数据安全
- 音频数据实时传输，不在服务器长期存储
- 图片数据支持Base64和URL两种方式
- MCP工具调用需要验证参数合法性
